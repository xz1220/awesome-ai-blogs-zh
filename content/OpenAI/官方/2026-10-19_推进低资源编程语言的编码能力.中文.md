我们最新的模型进展为构建和迁移低资源编程语言（如 COBOL、Fortran 和 Visual Basic）编写的软件带来了更强的能力。与 Python 和 JavaScript 等语言相比，这些语言可供模型学习的代码和文档更少，但它们支撑着世界各地的关键基础设施和基本服务。COBOL [支撑⁠](https://www.ibm.com/think/topics/cobol)着超过 40% 的网上银行系统、80% 的线下信用卡交易和 95% 的 ATM 交易，而 Fortran 则被用于[天气预报⁠](https://repository.library.noaa.gov/view/noaa/71120)和[核反应堆安全分析⁠](https://www.nrc.gov/education-regulatory-research/research/computer-codes)。提升 AI 处理这些语言的能力，可以帮助团队维护和现代化那些基本服务所依赖的软件。

这项工作的指引来自开发者和企业客户的反馈，他们告诉我们，编程模型在处理这些语言时往往力不从心。维护和现代化这类软件可能很困难：文档可能不完整，最初的开发者可能已经离开公司，而重要的业务规则可能只存在于代码之中。无论团队是在修复缺陷还是迁移到另一种语言，他们都需要保留其系统所依赖的行为。

为了衡量进展，我们开发了两项评估。MultiLangBench 测试模型能否在 20 种不同编程语言中从零开始构建一个与 SQLite 兼容的数据库引擎。我们的 COBOL 迁移评估则测试模型能否在保留程序行为的前提下，将现有程序迁移到另一种语言。两者结合起来，测试的是两项互补的技能：构建新软件，以及保留现有软件的功能。

我们最新的模型在这两项评估中都展现出显著提升，以更低的成本实现了高得多的准确率。

在 MultiLangBench 上，GPT‑6 Astra 在 20 种编程语言中取得了 87.4% 的平均测试通过率，高于 GPT‑5.6 Sol 的 26.8%，且在所有受测语言中均有提升。GPT‑6 Luna 的表现同样优于 GPT‑5.6 Sol，达到 40.3%，而预估 API 成本约降低 78%。

在我们的 COBOL 迁移评估中，GPT‑6.1 Sol 在低推理强度下取得了 86.6% 的准确率，而 GPT‑5.6 Sol 仅为 5.4%，同时成本降低 39%。在更高推理强度下，准确率达到 97.9%，几乎使该评估趋于饱和。

综合来看，这些结果表明我们的模型在处理各种编程语言方面正变得明显更强，同时也更具成本效益。

## 1. 从零构建 SQLite（MultiLangBench）

MultiLangBench 要求模型用指定的编程语言构建一个与 SQLite 兼容的数据库引擎。模型必须组织代码库、管理状态、处理错误，并在保留现有功能的同时添加新特性。

为了跨语言比较各实现，我们使用数据库文件作为共享接口。候选程序接收一个初始数据库和一条 SQL 查询，然后生成一个修改后的数据库。我们使用 SQLite 的参考实现来检查生成的数据库是否具有预期内容。这使我们能够应用相同的测试，而不受构建引擎所用语言的影响。

我们将 SQLite 现有测试套件中的测试适配为这种格式。该评估衡量模型在一次长时间的编码会话中能构建出多少可用的功能，并同时报告测试通过率和 API 成本。

在最高推理强度下，GPT‑6 Astra 在 20 种语言中取得了 87.4% 的平均测试通过率，高于 GPT‑5.6 Sol 的 26.8%。提升覆盖所有受测语言，包括 COBOL（10.9% 升至 72.1%）、OCaml（25.6% 升至 85.8%）、Fortran（21.4% 升至 83.5%）和 Visual Basic（27.5% 升至 89.4%）。Astra 在 20 种语言中的 19 种上得分超过 83%，其中 COBOL 仍是最难的，为 72%。

GPT‑6 Luna 提供了一个更低成本的选择，在所有受测语言中同样优于 GPT‑5.6 Sol。在最高推理强度下，其平均测试通过率达到 40.3%。提升包括 COBOL（10.9% 升至 17.1%）、OCaml（25.6% 升至 34.1%）、Fortran（21.4% 升至 31.4%）和 Visual Basic（27.5% 升至 41.6%）。这些提升所对应的预估平均 API 成本为每个样本 0.77 美元，相比之下 GPT‑5.6 Sol 为 3.48 美元，约降低 78%。

## 2. 迁移 COBOL 代码库

我们的第二项评估要求模型将 COBOL 程序迁移到 C++、Java、Kotlin、Python 或 Rust，同时保留每个程序的行为。

成功的迁移需要同时理解程序的业务逻辑和 COBOL 特有的语言行为。COBOL 程序通常处理金融交易和业务记录，其中诸如舍入规则和缺失记录处理等细节反映了业务需求。例如，除非显式要求舍入，COBOL 的定点算术会丢弃多余的小数位。一个改为对这些值进行舍入的重写版本，可能会在不报错的情况下运行，却产生不同的财务结果。

为了测试这些行为是否得到保留，我们在隐藏测试上评估模型，这些测试要求可观测输出逐字节一致。只有当所有测试都通过时，一次迁移才被视为成功。这类保留行为的能力对维护和现代化旧系统的团队很有用，不过将其应用于生产软件仍需要专家审查，并针对系统的业务规则和依赖进行测试。

在这项评估中，GPT‑6.1 Sol 在低推理强度下取得了 86.6% 的准确率，而 GPT‑5.6 Sol 在相同设置下为 5.4%，且 API 成本仅为其 61%。在更高推理强度下，准确率达到 97.9%，使该评估接近饱和。这些评估结果表明，在帮助团队现代化其业务所依赖的软件方面，我们正朝着更准确、更经济的代码迁移迈进。

## 提升面向企业软件的能力

这些评估，连同来自开发者和企业客户的直接反馈，帮助我们看清模型在哪些方面有所改进、在哪些方面仍然存在不足。

我们的目标是帮助模型将软件工程技能应用到更多语言中：理解不熟悉的代码库、规划变更、使用构建工具、运行测试以及调试失败。

你可以通过 API 在团队所用语言的编码任务上试用我们最新的模型。你关于哪些有效、模型在哪些方面力有不逮，以及我们接下来应聚焦哪些语言或工作流的反馈，将帮助我们改进模型的训练与评估方式，从而更好地支持你所依赖的软件。
